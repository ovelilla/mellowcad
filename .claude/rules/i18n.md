# Languages

> Verified against **next 16.4.2**, **next-intl 4.14.9**.

`docs/i18n-glossary.md` holds the words, their sources and how to write each language;
`docs/coverage/` what each language's command line does. Adding one: skill
`add-language`.

## Two languages, three catalogs

- **The interface language** is the URL's (`/`, `/es`, `/ar`). **The command language** is the
  engine's: command names and aliases, prompts, keywords, command-line messages, everything drawn
  on the canvas. `en` and `ar` use the global commands, `es` Spanish AutoCAD's.
- **The site's texts are in `messages/<locale>.json`** (next-intl), **the editor's in
  `packages/editor/src/locales/`**, **the engine's in `cad/locales/`** (`cad-catalogs.md`). What
  the engine names — snaps, entity types, tools, colours, ByLayer, aliases, preset views, the
  ViewCube's faces and compass — a host reads from the engine (`EngineState.names`, `state.tools`,
  `engineText()`), never copies into either.
- The engine's language contract for any host is `cad/README.md` (`cad/entryPoints.test.ts`).
- English is the source and the type: `AppConfig.Messages` is `typeof en`, and
  `createMessagesDeclaration` types every argument from `messages/en.json`. Its declaration,
  `messages/en.d.json.ts`, is generated by `next typegen` (in `npm run typecheck`) and ignored by
  git. `tsc` runs with `--incremental false`: the incremental cache misses a change in that
  declaration and reports — or hides — stale argument errors.
- **The editor's catalog works as the engine's**: `npm run locales` compiles it and writes
  `values.ts`, each message's arguments typed from English. Its keys are API: a new one is a minor,
  a renamed or removed one a major.

## URLs without a proxy

- `i18n/routing.ts` is the only list of languages. English has no prefix (`as-needed`), the others
  do; slugs are never translated.
- `i18n/rewrites.ts` builds the whole scheme, and `i18n/rewrites.test.ts` fixes it with Next's own
  matcher: redirects (`/en/…` → `/…`), `afterFiles` rewrites (English paths onto `/en/…`) and
  `fallback` rewrites (any unknown path of a language onto that language's 404). No `proxy.ts`: it
  would run a function on every visit to a static site; add one only if the language ever has to be
  negotiated.
- **Router requests reach the rewrites as file paths.** Vercel turns an `RSC` request into
  `/<path>.rsc` or `/<path>.segments/…` before `rewrites()` run; the generic rule carries those
  under `/en`, but the root arrives as `/index.…` while `[locale]` prerendered `/en.…`, so it has
  its own rules. Without them the home page's prefetch 404s on production only (`next dev` and
  `next start` route RSC by header). Check a new root-level rewrite with
  `curl -H "RSC: 1" -H "Next-Router-Segment-Prefetch: /_tree"` against the deployment.
- **Every site link is `localePath(locale, href)`** or `sitePaths()` (`i18n/navigation.ts`), held
  equal to next-intl's `getPathname` by a test. Never import `next-intl/navigation` into the app:
  `createNavigation` registers its client `Link` wherever it is imported (next-intl's client
  runtime on the landing), and its `Link` with a `locale` prefixes `/en`, a redirect.
- `[locale]` is a root param. Both root layouts export `generateStaticParams` over
  `routing.locales` and `dynamicParams = false`; `i18n/request.ts` reads `next/root-params`, and
  nothing calls `setRequestLocale`. Route handlers cannot read root params: they take `params` and
  name the locale (`getTranslations({ locale, namespace })`), as `global-not-found.tsx` names the
  default one. No metadata files inside `[locale]` (`marketing.md`).
- **A language's 404** is `[locale]/(marketing)/404/page.tsx` calling `notFound()`, prerendered and
  reached through the `fallback` rewrite, rendered by `(marketing)/not-found.tsx` inside the layout.
  Never a `[...rest]` catch-all: it renders on demand, a function per mistyped URL. Next sends a
  page's `notFound()` as an empty document with the 404 status and the metadata and draws its body
  in the browser. `global-not-found.tsx` (`experimental.globalNotFound`) is for what never reaches
  a language (`/404` itself).

## Messages

- Keys are semantic (`TopBar.save`), never the English sentence.
- **ICU, fully.** A number argument is `{count, number}`: a bare `{count}` is typed a string. A
  count that changes the words is `{count, plural, one {…} other {…}}`, never a pair of keys;
  every plural has `other`. A link or emphasis inside a sentence is a rich tag (`t.rich`).
  Messages are precompiled (the site's by `experimental.messages.precompile`): the browser gets
  icu-minify's formatter and no parser, and **`t.raw()` is off limits** (a message with arguments
  is an array).
- `mergeMessages` lays a language over English key by key, an array as a leaf: a missing key
  shows English, never the key.
- **A count is a plural wherever the language's words agree with it.** Arabic's noun changes with
  the number (`عنصر واحد`, `عنصران`, `3 عناصر`, `11 عنصرًا`), so its messages use the six categories
  where English prints a bare `{n, number}`; the test takes both as the same argument type.
- `i18n/messages.test.ts` and `packages/editor/src/locales/locales.test.ts`: every catalog parses,
  plurals have `other`, a translation has only English's keys, arguments and tags, and a `live`
  language has all of them.
- Command names inside prose (`Type a command (LINE, TR, CO…)`) are in that locale's command
  language — `LINEA`, `DF` in Spanish, the global ones in Arabic. So is a line that belongs to the
  command line, such as the 404's, which is the engine's own `unknownCommand`.
- A new contested Arabic term is marked † in `docs/i18n-glossary.md`.

## Left-to-right runs in right-to-left text

- A command name, a key, a value with its unit, an address or a URL inside Arabic text is isolated
  with FSI…PDI (U+2068…U+2069), written in the catalog as `⁨` and `⁩` so a translator
  sees them. Not a rich tag: it would have to exist in English too, and turn string props into
  nodes. The isolates work in HTML, attributes, metadata, the manifest and the share card
  (`lib/og.tsx` drops them before Satori).
- A name pasted from that prose into the command line still runs: `setCommandLineText` drops bidi
  controls.
- Markup in the command language carries its `lang` (`ui.md`; on the server
  `engineText(locale).commandTag`).

## Claims and copy

- **Never claim** DWG/DXF, printing or PDF, 3D, collaboration, cloud sync, mobile use or an
  installable offline mode until they exist. Never name the file extension: it is "MellowCAD's own
  versioned format".
- **"Free" and "open source" yes**: the repository is public on GitHub and its code is MIT. The
  licence covers the code, not the name or the logo — "the code is MIT", never "MellowCAD is MIT".
  Of the packages only `@mellowcad/engine` is on npm: link that one, and name `@mellowcad/react`
  and `@mellowcad/editor` only once they are published — but in the docs, which document all
  three and say "not published yet" while they are `private`. Their URLs are `REPOSITORY_URL` and
  `ENGINE_PACKAGE_URL`; a message links them with the rich tags of `sourceLinks`.
- Say only what the engine does: its prompts follow AutoCAD's order and keywords, not its wording —
  "same order, same option letters", not "same prompts".
- "AutoCAD" only nominatively ("works like AutoCAD", "AutoCAD commands"), with the trademark
  disclaimer in the footer. No Autodesk logos, colours or screenshots.
- **No number about the product is typed into the copy**: it is an argument from `lib/facts.ts`.
- **The Status section's «Not yet» and «Next up» are claims too**, written by hand: a change that
  ships one takes it off, in every language, in the same commit, and bumps `CONTENT_UPDATED`.
- Tone: calm and precise, with AutoCAD's dry humour. Short sentences. No hype words, no emojis, no
  shouting capitals in the sans.

## Where messages reach the browser

- **The landing never wraps its tree in `NextIntlClientProvider`.** An island takes its copy as
  props. A count it formats itself arrives as `pluralMessage(locale, (count) => t(key, { count }))`,
  one form per plural category, formatted with `formatPlural()` (`lib/plural.ts`: `Intl.PluralRules`
  and `Intl.NumberFormat`, no ICU runtime). A template with a slot the server cannot fill (the typed
  command of the 404 or the try-it box) comes from the engine with a placeholder and is filled in
  the island.
- **`/draw` ships no next-intl**: the editor reads its own catalog (`useEditorText`), a prop of
  `CadEditor`. A language module is data in the page, never `"use client"`.
- `Intl` always gets the page's locale (`getLocale()`, `getFormatter()`), never a literal `"en"`.

## No literals

ESLint holds it in `app/**`, `components/**` and the editor: `react/jsx-no-literals` for text,
allowing only signs the same in every language (`×`, `—`, `·`, `°`, `X`, `Y`, and the `→` that
`ForwardArrow` mirrors), and a literal `aria-label`, `title`, `placeholder` or `alt` is an error
too. A `label` prop of our own components is not seen: review holds it. Data that is not language
(a drawing number, a scale) is a named constant.

## Fonts per script

- Inter and Geist Mono are latin only. A script they lack gets a face on its own pages only:
  `scriptFontVariables` (`lib/fonts.ts`) overrides `--font-sans` and `--font-mono` on `<html>` with
  the face right behind Inter or Geist Mono and **before either fallback** — the fallback is a local
  Arial, which has Arabic and would take those letters first. The face is declared in both root
  layouts with `preload: false`: a preload in a shared layout fetches it on every page.
- Arabic is Readex Pro, variable, `subsets: ["arabic"]`, the lightest that works (IBM Plex Sans
  Arabic also breaks Satori's parser).
- `:lang(ar)` rules live in both stylesheets, unlayered so they outrank the utilities (`ui.md`).

## The engine's and the editor's language

- `loadEngineLocale` (`i18n/engine.ts`) and `loadEditorLocale` (`i18n/editor.ts`) map a page
  language to its catalog, one dynamic import apiece; English is built in, and a language missing
  from the `Partial` map silently shows English. `/draw` loads both on the server for
  `CadEditor`. The landing's figures: `marketing.md`.
- **What the engine draws is tagged with the command language** (`Scene.lang`, set by both
  presenters): a page's `lang` picks the font of a generic family, and an Arabic page's `monospace`
  drew the UCS icon's letters in another face.

## Draft and live

- `LOCALE_STATUS` decides. A `draft` language is built and reachable, `noindex`, and absent from the
  `hreflang` set, the sitemap and the language selector. `languageAlternates()` emits `hreflang`
  (every live language plus `x-default`) only once two are live.
- **The language selector is `LanguageLinks`** (`components/language-links.tsx`): the page being
  read in every live language, as plain `<a href hrefLang lang>` links named in their own language
  (`LANGUAGE_NAMES`, never a flag) — crawlable, and a full page load, since `lang`, `dir`, the fonts
  and the engine's catalog all change. It drops the language from `usePathname` (`unlocalizedPath`),
  which gives the same links on the server, where a prerender sees `/en/privacy`, and in the
  browser, which shows `/privacy`. The landing's footer and bar render it; `/draw` hands the
  editor's application menu the same links (`languageLinks`). The autosave has no language, so the
  drawing survives a switch.
- Each page's canonical, `og:locale`, JSON-LD `inLanguage`/`url`, manifest and share card are its
  language's (`pageMetadata`, `lib/structured-data.ts`).
- `<html lang dir>` comes from the locale in both root layouts, and `/draw` hands the editor the
  same `dir`.

## Budgets

What languages may add (gzip -9 unless it says Brotli), measured on a production build; a change
near one measures again against the build before it.

| What                                              | Budget                             |
| ------------------------------------------------- | ---------------------------------- |
| The English engine catalog, in the engine's chunk | ≤ 8 KB                             |
| Another language's engine catalog (own chunk)     | ≤ 12 KB                            |
| The editor's catalog in `/draw`'s HTML            | its language's only                |
| next-intl's runtime in the editor                 | none                               |
| A language's first load of the landing, Brotli    | ≤ 250 KB; 275 with a script's font |
| Functions per page visit                          | none: no proxy, all `○` or `●`     |
