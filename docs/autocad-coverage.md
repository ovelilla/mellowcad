# AutoCAD coverage

What each implemented command actually does, and which documented AutoCAD options it still lacks.
Read the row for a command **before extending it** — the gaps are deliberate and already researched.

This file is not auto-loaded. It has no `applyTo`. Update the affected row when you finish a feature;
do not append a narrative of the work.

Conventions used below: `missing:` lists options that exist in AutoCAD and not here. A parenthetical
gives the reason when the gap is blocked on something else rather than merely unbuilt.

## Coordinate systems

The UCS is planar: an origin (with a Z) and an X axis in the world's XY plane, Z always the world's
(tilting it needs a normal per entity and a view off the plan: roadmap item 2). Entities are stored
in the WCS.

text angle of a dimension (Angle), the default spacing ARRAYRECT offers (from
world extents), and palette rotations (they stay in the WCS, as AutoCAD's TEXT and INSERT rows do).

**Where a point's Z comes from:** an object snap gives the object's Z there (OSNAPZ 0, not exposed;
a line's is interpolated along it, and Intersection needs the two objects to meet in 3D, while
Apparent Intersection takes the first one's — **unverified**, the help only says it snaps where two
objects "do not intersect in 3D space"); an OTRACK point the acquired point's (**unverified**); an
absolute point typed without a Z, or the bare cursor, ELEVATION above the XY plane of the UCS
(ELEV and DIST say so; one conceptual page keeps the last Z instead); a relative one, a
typed length or angle, the last point's. Ortho, Polar and the snap lattice leave it alone. What LINE
draws has a Z at each end; a flat object (PLINE, SPLINE, CIRCLE, ARC, ELLIPSE, RECTANG, POLYGON,
TEXT, MTEXT, ATTDEF, INSERT) lies in the plane of the first point that fixed it,
and the others are projected onto it — what AutoCAD's PLINE does; its CIRCLE and ARC by two or three
points at different heights tilt into their own plane instead (deviation until roadmap item 2). A dimension
lies at the height of the point that places its dimension line, whatever its origins': snapped on
objects above the plane, AutoCAD's is still "created at the current elevation" (Autodesk forum 2016,
AUGI 2010); DIMBASELINE / DIMCONTINUE take the base dimension's, and a location snapped to an object
its Z (**unverified**). Its origins' own Z is not kept (one elevation per dimension here; AutoCAD
keeps each definition point's).
MOVE, COPY, STRETCH and PASTECLIP displace in 3D, SCALE scales about a 3D base point, and BLOCK's
base point and the clipboard's have a Z. LINE, CIRCLE, ARC, PLINE and POLYGON give what they draw
the THICKNESS; RECTANG uses its own and TEXT none. The editing commands keep the Z: TRIM, EXTEND and
BREAK work in plan (PROJMODE 1, EDGEMODE 0, not exposed) and give a line's new end the Z along its
slope; OFFSET keeps the plane, rise and thickness; FILLET, CHAMFER and JOIN need their objects in one
plane; HATCH lies in its boundary's; a grip drags to a point as a click does.

## The landing's live sketch

"Try it here" on `/` turns the hero's flange into the editor's own engine, dynamic-input box and
command line, embedded in the page (`CadEngine` with a `scope` and a memory `store`). Commands,
prompts, aliases, snaps, tracking and the F-keys behave as in the editor. It deviates only where the
page is not the engine's or the sheet has no room:

- Keys reach it only while it is in use — after a press or a focus inside it — and the wheel zooms
  only then; otherwise it scrolls the page (AutoCAD zooms on any wheel turn over the drawing, which
  in a scrolling page would trap the scroll). Space and the arrows the runtime passes on never
  scroll the page while it is in use.
- Esc cancels as in AutoCAD and never leaves the sketch; Tab does, and "Close" is always in view.
- No toolbar, palettes or status bar: commands are typed. The Shift+right-click osnap menu is not
  offered (it closes if opened), and Selection cycling shows the badge without the Selection list
  box.
- It autosaves to the page's memory, never to this device's store. "Open in the full editor" hands
  it over, and asks first — download the sketch, replace the drawing or cancel — when there is a
  drawing the editor would restore.

## Roadmap

Agreed ordering. The rule behind it: **close model gaps before command gaps**, because every new
entity type multiplies the "Adding an entity type" checklist that a normal per entity would force
us to walk again, whereas a command costs the same before or after it.

1. **Z in the model (2.5D)** — done: Z along the world's Z with the normal fixed at +Z, stored as
   DXF stores it (what each command does with it is in its row and under "Where a point's Z comes
   from"). 3D solids (ACIS: B-rep, booleans, shading) are off the roadmap: a separate kernel the size
   of everything built so far, which neither reuses nor cheapens any of this — a product decision,
   not a debt.
2. **Views and the tilted plane** — next: VPOINT, `-VIEW` presets and the projection from 3D to the
   screen that draws elevation and thickness, together with a normal per entity (DXF 210, the OCS)
   and the UCS options that tilt the XY plane (Face, X, Y, ZAxis, a third point off the plane). They
   go together because an object drawn on a tilted plane needs its own normal, and from the plan that
   plane is seen edge-on. The same work lifts the 2.5D deviations: CIRCLE and ARC through points at
   different heights, FILLET and CHAMFER of sloping lines in one plane (JOIN's 3D polyline waits for
   3DPOLY). The brief is `docs/next-views.md`.

Left out of the 2.5D model, each a gap of its own: SPLINE 3D (a 3D NURBS kernel) and 3DPOLY, LIST,
the `.X` / `.XY` point filters, OSNAPZ as a variable, ARRAYRECT's Levels, CHPROP, and POINT's
thickness (with POINT, below).

Editing a spline — OFFSET (which is also what the ellipse's OFFSET and FILLET wait for), TRIM /
EXTEND / BREAK / JOIN, SPLINEDIT — is a command gap, so it queues behind the model gap above.

Deferrable indefinitely at no extra cost: PASTEBLOCK/PASTEORIG/CUTBASE, DIMARC, DIMORDINATE, the
modern `DIM` command, POINT with DIVIDE/MEASURE, XLINE/RAY, GROUP, LENGTHEN, ALIGN, per-object
ltscale, isometric drafting mode.

Blocks family, not on the near-term path: ByBlock resolution, non-uniform scale (the ellipse exists
now; what is left is a per-axis scale vocabulary), inserting external drawing files + INSUNITS,
`-BLOCK` Mode keywords, `-INSERT` Basepoint/Corner/XYZ/Explode/Repeat, BASE, WBLOCK, BEDIT, MINSERT,
XREF, BREPLACE, dynamic blocks, DIVIDE/MEASURE with a block, a block table manager, ATTSYNC,
BATTMAN, ATTEXT / DATAEXTRACTION, multiline attributes.

DXF import/export and plot-to-PDF remain end-of-roadmap and unscheduled.
