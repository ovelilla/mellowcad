COPYCLIP copies the objects you select to the clipboard, with the layers, styles and blocks they use; the drawing does not change, and objects selected before it stay selected. Ctrl+C runs it, cancelling a command that is running. `PASTECLIP`, Ctrl+V, then asks for an insertion point: the objects follow the cursor and land with the lower-left corner of their extents at the point, in the current UCS, all in one step that `U` takes back. Paste into the same drawing or another one: the clipboard is the system's, so a drawing in another tab can read it, if the browser lets the page read the clipboard. Where a pasted layer, style or block has the name of one the drawing already has, the drawing's own is used.

`CUTCLIP`, Ctrl+X, copies the objects and erases them, as ERASE does. `COPYBASE`, Ctrl+Shift+C, asks for a base point first, and PASTECLIP then places the objects by that point instead of their corner, so they land exactly where you mean. Ctrl+A selects every object in the drawing.

- **Command:** `COPYCLIP`
- **Panel:** [Files & clipboard](/docs/commands#files)
- **Try it:** [Open the editor](/draw), type `COPYCLIP` and press Enter.

## Questions [#questions]

### What is the difference between COPY and COPYCLIP?

[`COPY`](/docs/commands/copy) places copies in the same drawing, from a base point to a second point. COPYCLIP puts the objects on the clipboard, to paste with PASTECLIP into this drawing or another.

### How do I copy with a base point?

Press Ctrl+Shift+C, or type `COPYBASE`, give the base point and select the objects. Ctrl+V then places them by that point.

### How do I copy objects from one drawing to another?

Select them and press Ctrl+C, open the other drawing and press Ctrl+V, then pick the insertion point. Their layers, styles and blocks come with them.

### Why does paste not work?

The browser may ask whether the page can read the clipboard: allow it. If it refuses, PASTECLIP pastes what was last copied in the same page. With nothing copied, it pastes nothing.
